## 목적

스테이지 1의 검증된 전투·보상에서 출발해 첫 계정의 25초 준비, 초기 코인 가격, 스테이지 2·3 문 가격과 첫 `7,000 Defense XP` 도달 시간을 검증합니다.

유효 범위:

```text
- 첫 환생 도달 시간
- 첫 15분 구매 밀도
- 초기 문 가격과 코인 수집 가정
- 첫 환생 전 스테이지 전환 시나리오
```

환생 시 코인·문·전투가 초기화된다는 이전 가정은 폐기했습니다. 두 번째 이후 요구량은 `V1_REBIRTH_XP_BENCHMARK.md`를 따릅니다.

---

## 1. 최초 계정 안전장치

```text
첫 수동 굴리기
→ 첫 타워 빈 슬롯 자동 배치
→ 초원 슬라임 1마리
→ 코인 10·Defense XP 10
→ 자동 굴리기 10코인 구매
→ 4초 간격 세 번 굴림
→ 4슬롯 완성
→ 약 25초에 정규 웨이브 1
```

- 별도 약화 몬스터 없음
- 추가 보너스 재화 없음
- 빈 슬롯 채움은 기존 타워를 교체하지 않음
- 계정당 한 번만 실행

## 2. 입력값

### 스테이지 1

```text
StageCoinUnit: 1
보스 CoinRewardModifier: 1.15
보스 DefenseXPModifier: 1.15
5웨이브 주기: 56.28초
주기 코인 가치: 400
주기 Defense XP: 400
```

| 웨이브 | 가치 |
|---:|---:|
| 1 | 60 |
| 2 | 75 |
| 3 | 70 |
| 4 | 70 |
| 5 | 125 |
| 합계 | **400** |

### 굴리기

```text
기본 간격: 4.0초
굴리기 속도 I: 3.6초
```

### 문

```text
스테이지 2: 750코인
스테이지 3: 3,200코인
```

문은 영구 개방입니다.

### 첫 환생

```text
FirstRebirthXP = 7,000
TokenReward = 4
```

## 4. 직접 수집 가정

```text
기본 수집 효율: 75%
자석 범위 I 이후: 85%
자석 속도 I 이후: 92%
```

실제 코인은 모두 물리적으로 존재합니다. 수치는 맵 이동과 놓치는 코인을 나타내는 계획용 평균값입니다.

## 5. 상위 스테이지 프록시

실제 스테이지 2·3 콘텐츠 작성 전 첫 환생 경제용 가정:

| 스테이지 | StageRewardScale | 계획 주기 |
|---:|---:|---:|
| 1 | 1.000 | 56.28초 |
| 2 | 약 2.3268 | 66초 |
| 3 | 약 5.4139 | 78초 |

이 프록시는 첫 환생 시점 계산에만 남겨 둡니다. 두 번째 이후 환생의 계획 주기는 새 XP 벤치마크에서 별도로 정의합니다.

전투 준비 시나리오:

```text
stage1_only
- 첫 환생 전까지 스테이지 1

slow_stage2
- 5분부터 스테이지 2 방어 가능

median_stage2
- 3분 30초부터 스테이지 2
- 10분부터 스테이지 3

fast_stage2
- 2분 30초부터 스테이지 2
- 7분부터 스테이지 3
```

## 8. 현재 환생 결과

```text
Defense XP 7,000 이상
→ 환생 실행
→ Defense XP 0
→ RebirthCount +1
→ RebirthStatTokensEarned +4
→ UnspentRebirthStatTokens +4
```

변경하지 않음:

- 코인
- 열린 문
- 현재 스테이지·웨이브·몬스터
- 바닥 코인
- 타워·코인 스탯·포션

두 번째 이후에는 `RebirthXPAnchorStage`와 20/35/50분 목표 곡선을 사용합니다.
