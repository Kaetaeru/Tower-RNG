## 목적

환생 후 코인·문·현재 스테이지와 전투가 유지되는 구조에서 두 번째 이후 환생 요구량을 정의합니다.

단순한 `7,000 × RebirthCount^지수` 방식은 사용하지 않습니다. 스테이지별 Defense XP 수입이 기하급수적으로 증가하기 때문에, 요구량도 플레이어가 실제로 XP를 얻은 가장 높은 스테이지의 기준 수입에 맞춰 계산합니다.

---

## 1. 첫 환생

```text
FirstRebirthXP = 7,000
```

기존 첫 경제 벤치마크를 유지합니다.

```text
최단 약 7.80분
중앙 약 9~10분
최장 약 14.34분
```

첫 환생은 토큰 4개를 처음 얻는 시점입니다.

---

## 2. XP 기준 스테이지

```text
RebirthXPAnchorStage
= Defense XP를 한 번 이상 획득한 가장 높은 스테이지
```

- 문에 들어가기만 해서는 기준이 상승하지 않음
- 높은 스테이지에서 첫 유효 처치 XP가 발생하면 상승
- 한 번 상승한 기준은 감소하지 않음
- 현재보다 낮은 스테이지를 파밍하면 환생 진행이 느려질 수 있음

높은 스테이지 행운만 받기 위해 입장하는 전략은 그대로 허용합니다. 실제 XP를 얻기 전에는 요구량이 변하지 않습니다.

---

## 3. 기준 상승 시 진행률 보존

높은 스테이지에서 첫 XP를 획득하면 요구량이 커지지만, 현재 진행 퍼센트는 그대로 유지합니다.

```text
ProgressRatio
= CurrentDefenseXP / OldRequiredDefenseXP

NewRequiredDefenseXP
= Requirement(NextRebirth, NewAnchorStage)

NewCurrentDefenseXP
= ProgressRatio × NewRequiredDefenseXP
```

예:

```text
기존 진행률 37.25%
→ 기준 스테이지 상승
→ 현재 XP 숫자와 요구 XP 숫자가 함께 증가
→ 진행률은 계속 37.25%
```

이 규칙은 두 문제를 동시에 막습니다.

- 높은 스테이지 진입으로 XP 막대가 뒤로 밀리는 체감
- 낮은 요구량을 유지한 채 높은 스테이지 XP만 받는 악용

---

## 4. 목표 환생 간격

첫 환생 이후의 기준 처리시간입니다.

```text
두 번째 환생: 20분
세 번째 환생: 35분
네 번째~50번째 환생: 50분
```

이는 스탯이 없는 기준 편성의 목표 시간입니다. 성능 투자와 좋은 타워는 실제 시간을 단축할 수 있습니다.

V1 숙련 범위를 넘은 장기 성장:

```text
51~100번째: 55분
101~150번째: 60분
151~200번째: 65분
201번째 이후: 최대 70분
```

V1의 20~30시간 구간에서는 대부분 50분 기준을 사용합니다.

## 5. 요구량 공식

```text
PlannedDefenseXPPerMinute(Stage)
= PlannedCycleDefenseXP(Stage)
× 60
/ PlannedFarmCycleSeconds(Stage)
```

```text
RequiredDefenseXP(NextRebirth, AnchorStage)
= NiceRound(
    PlannedDefenseXPPerMinute(AnchorStage)
    × TargetRebirthMinutes(NextRebirth)
  )
```

V1 계획용 주기 XP:

```text
PlannedCycleDefenseXP(Stage)
= 400 × StageRewardScale(Stage)
```

실제 스테이지 웨이브가 작성되면 해당 스테이지의 실제 BaseBudget 주기와 FarmTargetSeconds로 교체합니다.

`NiceRound`는 세 자리 유효숫자로 반올림합니다.

## 8. 성능 스탯의 간접 XP 가속

성능 스탯은 Defense XP를 직접 곱하지 않습니다. 그러나 웨이브를 더 빨리 끝내므로 실제 분당 XP가 증가합니다.

시뮬레이션 근사:

```text
ActualDefenseXPRateMultiplier
= PerformanceMultiplier ^ 0.60
```

지수 `0.60`은 생성 간격·이동·보스 시간 때문에 전체 주기가 순수 DPS의 역수만큼 줄어들지 않는다는 가정입니다.

실제 Roblox 웨이브 데이터가 생기면 이 근사를 제거하고 실제 처리시간을 사용합니다.

## 12. 해석

- 환생은 약 20~50분마다 보이는 장기 목표가 됨
- 스테이지가 올라가도 환생이 몇 초로 축소되지 않음
- 높은 스테이지를 실제로 파밍할 수 있어야 그 기준 XP율을 사용 가능
- 성능 투자는 토큰 성장까지 가속하지만 무한 증폭하지 않음
- 재화·행운·속도 빌드도 환생이 완전히 정지하지 않음
- 코인·문·전투 초기화가 없어도 환생의 반복 목표가 유지됨

---

## 13. 아직 미확정인 값

- 스테이지 2~15 실제 5웨이브 XP 총량과 파밍 주기
- 실제 타워 분포에 따른 성능 스탯의 clear-speed 탄력성
- 베이스 누수와 실패 시간이 환생 속도에 미치는 영향
- 빠른·느린 스테이지 도달 경로
- 50회 이후 장기 환생 시간의 실제 체감

실제 스테이지가 작성될 때 계획 XP율을 하나씩 실제값으로 교체합니다.
