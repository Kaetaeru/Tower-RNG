## 요약

몬스터는 타워와 같은 3D 모션 견본 방식을 사용합니다. `Basic` 모델과 자유 이름의 모션 견본을 제작하고, 공통 시각 상태 애니메이터가 이름·상대 경로를 기준으로 런타임 모델을 변화시킵니다.

모션 엔진은 공유하지만 행동 흐름은 타워와 분리합니다. 몬스터는 경로 이동, 특수 행동, 피격, 사망과 베이스 도달을 중심으로 별도의 행동 모듈을 가집니다.

---

## 1. 공유하는 모델링 규약

몬스터는 `TOWER_MODELING.md`의 다음 규칙을 재사용합니다.

- 3D `Model` 기반 제작
- 예약 이름 `Basic`
- 자유롭게 이름 붙인 모션 견본
- 모션 모델 자체를 보이는 모델로 교체하지 않음
- 런타임에는 `Basic` 복제본 하나만 사용
- 이름과 모델 내부 상대 경로로 구성요소 대응
- 위치·회전뿐 아니라 크기, 색상, 투명도, 재질, 조명과 파티클 등의 시각 상태 처리
- 게임 판정과 물리 설정은 모션 견본에서 복사하지 않음

예시:

```text
GoblinKit
├─ Basic
├─ WalkA
├─ WalkB
├─ Hurt
├─ Rage
├─ Death
└─ GoblinModule
```

`Walk`, `Hurt`, `Death`는 예시이며 고정 이름이 아닙니다.

---

## 2. 몬스터 행동 흐름

몬스터 행동 모듈은 타워 공격 문법과 별도로 다음 흐름을 다룹니다.

```text
생성
→ 경로 이동
→ 조건부 특수 행동
→ 피격 및 상태 변화
→ 사망 또는 베이스 도달
→ 정리
```

몬스터마다 필요한 모션만 자유롭게 구성할 수 있습니다.

예:

```lua
context:PlayPose("Emerge", 0.25)
context:StartMoveLoop({"StepLeft", "StepRight"})
context:FollowPath()
```

정확한 공개 함수와 파일 구조는 구현 명세에서 확정합니다.

---

## 3. 이동과 포즈 분리

몬스터의 경로상 위치 이동과 파츠 모션은 별도 레이어로 처리합니다.

```text
Root Movement
- 웨이포인트 경로 이동
- 이동속도 변화
- 밀치기 또는 짧은 위치 변화

Pose
- 걷기, 부유, 기어가기
- 특수 행동 자세
- 피격 및 사망 상태

Overlay
- 피격 반짝임
- 변종 광택
- 상태 효과 표시
```

경로 이동과 걷기 모션이 같은 CFrame을 서로 덮어쓰지 않아야 합니다.

---

## 4. 변종과 공유 키트

변종 몬스터는 다음 방식 중 하나를 사용할 수 있습니다.

- 같은 Basic과 모션을 사용하고 색상·재질·효과만 변경
- 같은 행동 모듈과 별도 모델 키트 사용
- 별도 행동과 별도 모델 키트 사용

변종이라고 해서 반드시 완전히 새 리그나 애니메이션 시스템을 만들 필요는 없습니다.

---

## 5. 사망과 베이스 도달

사망과 베이스 도달은 서로 다른 종료 이유입니다.

- 사망: 처치 보상과 코인 드롭 발생
- 베이스 도달: 처치 보상과 코인 드롭 없이 제거

종료 연출은 판정 완료를 불필요하게 지연시키지 않습니다. 사망 모델이나 효과는 시각적으로 잠시 남을 수 있지만 전투 대상에서는 즉시 제외할 수 있어야 합니다.

---

## 6. 제작 검증

몬스터 키트 검증기는 최소한 다음을 확인합니다.

- `Basic` 존재
- 같은 부모 아래 중복 이름
- 모션 견본과 Basic의 상대 경로·클래스 불일치
- 존재하지 않는 모션 호출
- 경로 이동 중 Root와 Pose 충돌 가능성
- 사망·제거 후 남은 반복 모션과 효과

오류가 게임 전체 제작을 막기보다 구체적인 경고와 해당 경로를 제공하는 방향을 우선합니다.

---

## 7. 미확정 사항

- 몬스터 행동 Context의 정확한 공개 함수
- 피격 모션의 중첩과 우선순위
- 사망 연출의 최대 유지 시간
- 대규모 몬스터에서 모션 갱신을 간소화하는 LOD 규칙
- 변종 외형 오버라이드의 최종 데이터 형식
