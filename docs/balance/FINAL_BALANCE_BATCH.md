# V1 최종 밸런스 계산 배치

- 계층: 계산·검증
- 상태: **Active Batch Checklist**
- 프로젝트 현황: `../PROJECT_STATUS.md`
- 계산 인덱스: `INDEX.md`
- 콘텐츠 카탈로그: `../catalog/INDEX.md`
- 마지막 정리: 2026-08-03

## 목적

남아 있는 계산을 사용자 확인 요청으로 하나씩 끊지 않고, 의존성 순서에 따라 하나의 최종 배치로 처리합니다.

```text
각 계산은 별도 공식·스크립트·문서를 유지
→ 단계별 수용 조건 검사
→ 기준을 벗어난 경우에만 하위 계산 재실행
→ 모든 계산 완료 후 최종 권고값 묶음 작성
→ 그 뒤에만 카탈로그 채택 시작
```

한 거대한 계산식으로 모든 시스템을 섞지 않습니다. 중간 오류를 추적할 수 있도록 계산 책임은 계속 분리합니다.

---

# 고정 원칙

- 계산과 카탈로그는 계속 분리합니다.
- 계산 중 임시 이름·가격·배율은 카탈로그 완료로 세지 않습니다.
- 각 단계는 재현 스크립트와 수용 조건을 가집니다.
- 기존 확정 규칙과 충돌하는 값을 조용히 덮어쓰지 않습니다.
- 실제 설계 충돌이 발견될 때만 사용자 판단을 요청합니다.
- 수치 차이가 재계산 기준보다 작으면 기존 장기 계산을 유지합니다.

합체 비용의 현재 확정 해석:

```text
합체 실행 비용
- 같은 TowerId 재료 수량
- 추가 코인 0
- 추가 정수 0

코인으로 구매하는 것
- 합체 시스템 영구 해금 노드
- 필요하면 계보 확장 노드
```

따라서 후속 합체 계산에서 임의의 매회 코인 수수료를 추가하지 않습니다.

---

# 입력 동결

최종 배치가 시작할 때 다음 값을 입력 버전으로 기록합니다.

- 일반 타워 50자리 확률표
- 시간대별 굴림 수와 보유 전력 분포
- 4→12슬롯과 역할 상한
- 지원·제어 중첩 계약
- 변종 계열 확률·PowerBudget·해금 가격
- 스테이지 1~15 검증 주기와 보상
- 문·슬롯·코인 전투 통합 경제
- 환생 XP와 네 분야 스탯
- 오프라인 코인 원칙

하위 단계가 이 입력을 바꾸면 영향을 받는 단계만 다시 실행합니다.

# 최종 계산 순서

## BAL-FINAL-001 — 수동 합체

계산 항목:

- 기본형과 변종의 실제 중복 수량
- 단계별 필요 재료 수
- 합체 결과 PowerBudget
- 슬롯 압축 가치
- 최초 합체 가능 시간
- 5·15·30시간 합체 보유 분포
- 합체 해금·계보 확장 노드 가격
- 자동 편성의 합체 결과 평가

수용 조건:

- 2~4시간에 첫 합체 시스템 경험 가능
- 합체가 12~15시간 완주의 필수 조건이 아님
- 재료 세 개의 총 전력을 그대로 한 슬롯에 보존하지 않음
- 슬롯 압축을 포함해도 중앙 전투력 증가가 완주 곡선을 붕괴시키지 않음
- 극희귀 기본형을 흔한 합체가 즉시 역전하지 않음

상태: `[ ]`

## BAL-FINAL-002 — Roblox 런타임 손실

계산 항목:

- 오버킬과 예약 피해
- 투사체 이동시간
- 타겟 사망 뒤 재탐색
- Engage 접근·재접근
- 애니메이션 판정 프레임
- 서버 틱과 동시 명중 순서
- 저·중·후반 역할 조합별 RuntimeEfficiency

수용 조건:

- 중앙 런타임 손실이 별도 보정 없이 설명 가능
- 스테이지 15 P10이 실제 행동 손실 뒤에도 최초 클리어 가능
- 손실 10% 초과 구간은 원인과 완화 규칙 기록
- 계산보다 Roblox가 10% 이상 느리면 관련 스테이지 재검증 대상으로 표시

상태: `[ ]`

## BAL-FINAL-003 — 오프라인 코인

계산 항목:

- 최고 검증 스테이지별 기준 코인율
- 25→40% 효율 단계
- 8→12→24시간 저장 단계
- 해금·업그레이드 가격
- 재화 환생 스탯과의 결합
- 로그아웃·수령 시점 배율 악용 방지
- 1일·3일·7일 부재 민감도
- 빠른·중앙·느린 계정의 문·슬롯 구매 영향

수용 조건:

- 오프라인만으로 타워·Defense XP·환생·스테이지 클리어 불가
- 온라인 파밍보다 항상 낮은 시간당 코인
- 24시간 최대 보상이 장기 핵심 경제를 즉시 완성하지 않음
- 높은 스테이지 잠깐 입장 악용 불가

상태: `[ ]`

## BAL-FINAL-004 — 후반 코인 싱크 통합

계산 항목:

- 문·슬롯·전투 노드
- 변종 가지 25.0185B
- 합체 해금·계보 확장
- 오프라인 가지
- 아직 필요한 편의·수집 반복 싱크
- 15·20·25·30시간 잔여 코인
- 소비 전략별 완료 시점

수용 조건:

- 메인 완주 전 필수 성장과 선택 수집 싱크 구분
- 20~30시간에 모든 코인이 무의미하게 남지 않음
- 후반 싱크가 극희귀 획득을 강제하지 않음
- 코인 부족 때문에 중앙 완주가 15시간을 크게 넘지 않음

상태: `[ ]`

## BAL-FINAL-005 — 전체 계정 경로 재실행

계산 항목:

- 빠른·균형·느린 소비 전략
- P10·P50·P90 타워 보유 운
- 지원·제어 중첩
- 변종
- 합체
- 런타임 손실
- 오프라인 코인 민감도
- 스테이지 15 최초 클리어와 안정 파밍

검증 목표:

```text
빠른 메인 완주 8~10시간
중앙 메인 완주 12~15시간
느린 메인 완주 18~22시간
V1 숙련 20~30시간
```

수용 조건:

- 특정 1/N 타워·변종·합체 결과가 완주 필수가 아님
- P10 계정도 확정 성장과 정상 역할 조합으로 완주 가능
- P90 계정이 지나치게 이른 시간에 전체 콘텐츠를 무력화하지 않음
- 느린 경로가 빠른 경로의 두 배를 크게 넘지 않음

상태: `[ ]`

## BAL-FINAL-006 — 최종 권고값 묶음

산출물:

- 카탈로그 채택 후보 가격
- 최종 확률·PowerBudget·재료 수량
- 시스템별 공식과 상한
- 변하지 않는 값과 추가 플레이테스트가 필요한 값 구분
- Roblox 수직 슬라이스에서 먼저 구현할 최소 수치 집합
- 남은 위험과 런타임 재검증 항목

이 단계는 `docs/balance`의 권고안만 작성합니다. 실제 TowerId·NodeId·MonsterId·표시 이름과 채택 수치는 별도 카탈로그 작업에서 확정합니다.

# 보고 방식

최종 배치 중간에는 다음 경우에만 사용자 판단을 요청합니다.

- 기존 확정 기획과 새 계산이 직접 충돌
- 두 선택지가 모두 수치상 통과하지만 플레이 경험이 크게 다름
- 카탈로그 정체성이나 과금 원칙을 바꿔야만 통과 가능

그 외에는 각 단계를 순서대로 완료하고, 마지막에 다음을 한 번에 보고합니다.

```text

진행 체크리스트

```
