## 요약

변종은 기존 타워의 모델·모션·행동 골격을 재사용하면서 색상·재질·효과와 고정 강화 능력을 추가하는 별도 TowerId입니다.

게임 시작 시에는 등장하지 않습니다. 플레이어가 코인 스탯 트리에서 계열과 허용 범위를 영구 해금한 뒤, 무료 굴림으로 선택된 기본 타워에 별도 변종 티켓을 판정합니다.

```text
기본 타워 선택
→ 변종 티켓 판정
→ 해금·허용된 계열이면 변종 지급
→ 아니면 기본형 지급
```

변종은 기본형보다 강하지만 V1 완주에 필수적인 성장축으로 사용하지 않습니다. 중후반 수집 목표, 희귀 획득 연출과 후반 코인 소비처가 주된 역할입니다.

---

## 1. 정의

- 변종마다 고유 TowerId
- 동일 변종은 항상 동일 성능·외형
- 개체별 무작위 옵션 없음
- 기본형 자산 공유 가능
- 역할 정체성 유지
- 색상만 바꾸고 성능 차이 없는 결과 금지
- 일반 타워와 같은 ID별 수량 저장 계약 사용

예:

```text
왕실 기사
인화성 왕실 기사
독성 왕실 기사
공허의 왕실 기사
거대 왕실 기사
```

모든 타워에 모든 변종을 강제하지 않습니다. 각 기본 타워는 카탈로그에서 허용 계열을 명시합니다.

---

## 2. 공통 계열

### 인화성

- 불꽃·연기·열 흔들림
- 지속 피해·폭발·전파
- 계열 판정 공식 기본값 `1 / 5,000`

### 독성

- 녹색·보라색·독 안개
- 중첩 독·지속시간·전염
- 계열 판정 공식 기본값 `1 / 10,000`

### 공허

- 검정·보라색·공간 왜곡
- 연쇄·순간이동·처치 반응
- 계열 판정 공식 기본값 `1 / 20,000`

### 거대

- 모델·실루엣·효과 확대
- 높은 피해·범위·대상 수
- 더 무거운 모션과 음향
- 계열 판정 공식 기본값 `1 / 50,000`

계열 수치는 `Confirmed (Provisional Balance)`이며 최종 TowerId와 행동값은 카탈로그 채택 단계를 거칩니다.

---

## 3. 해금과 허용 범위

### VAR-001: 계열 해금

- 게임 시작 시 모든 계열 비활성
- 거대 코인 스탯 트리의 특수 시스템 가지에서 해금
- 해금한 계열만 판정 가능
- 구매 결과 영구 유지
- 환생 후 초기화 없음
- Robux로 계열을 직접 해금하지 않음

### VAR-002: 세 단계 허용 범위

각 계열은 별도의 허용 범위를 가집니다.

```text
계열 해금
- 공식 확률표 1~12번 기본 타워

확장 I
- 공식 확률표 1~31번 기본 타워

확장 II
- 공식 확률표 1~50번 전체
```

의도:

- 최초 해금으로 `1/10`, `1/20` 기본군 변종을 먼저 제공
- 확장 I에서 반복 분모군과 `1/1000` 기본군까지 개방
- 확장 II는 극희귀 변종을 원하는 숙련 수집가용 선택 노드
- 확장 구매 없이도 메인 완주 가능

가격과 목표 시점은 `V1_TOWER_VARIANT_BENCHMARK.md`의 계산 권고안을 사용하며 카탈로그에서 최종 채택합니다.

## 4. 변종 판정

### VAR-003: 두 단계 굴림

```text
1. 기존 일반 확률표와 현재 Compression으로 기본 타워 선택
2. 별도의 변종 티켓에서 계열 구간 판정
3. 기본 타워가 해당 계열을 허용하고 해금 범위 안이면 변종 지급
4. 조건이 하나라도 맞지 않으면 원래 기본형 지급
```

한 굴림은 항상 타워 하나만 지급합니다. 기본형과 변종을 동시에 주지 않습니다.

### VAR-004: 고정 비중첩 티켓

네 계열은 하나의 고정 티켓 안에서 서로 겹치지 않는 구간을 사용합니다.

- 한 굴림에서 변종 최대 1개
- 잠긴 계열의 구간은 다른 계열로 재분배하지 않음
- 허용되지 않은 계열이 나오면 기본형 지급
- 새 계열을 해금해도 기존 계열의 확률은 변하지 않음
- 내부 가족 가중치 정규화 사용 금지

모든 계열이 활성이고 기본 타워가 전부 허용된 원시 합계:

```text
1/5,000 + 1/10,000 + 1/20,000 + 1/50,000
= 0.00037
≈ 1 / 2,702.70
```

### VAR-005: 행운과 특수 주사위

일반 행운, 황금 주사위와 다이아몬드 주사위는 **기본 타워 선택**에 정상 적용합니다.

변종 계열 티켓 자체에는 추가 Compression을 적용하지 않습니다.

```text
행운 증가
→ 희귀 기본 타워가 먼저 선택될 가능성 증가
→ 그 희귀 기본 타워의 변종 기회도 간접 증가

행운 증가
↛ 계열 1/5,000 자체를 별도로 압축
```

이는 기본 타워 행운과 변종 행운이 이중으로 곱해지는 문제를 막습니다.

## 5. 공식 확률과 표시

### VAR-006: 최종 공식 분모

```text
VariantBaseOddsN
= BaseTowerOddsN × FamilyOddsN
```

예:

| 기본 타워 | 계열 | 최종 공식 확률 |
|---:|---:|---:|
| `1 / 10` | 인화성 `1 / 5,000` | `1 / 50,000` |
| `1 / 10` | 거대 `1 / 50,000` | `1 / 500,000` |
| `1 / 1,000` | 공허 `1 / 20,000` | `1 / 20,000,000` |
| `1 / 10^20` | 거대 `1 / 50,000` | `1 / 5 × 10^24` |

최종 `BaseOddsN`은 임의 정밀도 문자열로 카탈로그에 기록합니다.

### VAR-007: 플레이어 표시

표시:

- 변종의 최종 공식 기본 `1 / N`
- 변종 계열
- 기본형과 달라진 핵심 능력
- 보호·합체 가능 여부

표시하지 않음:

- 현재 행운 적용 유효 확률
- 현재 계정의 허용 질량
- 내부 티켓 구간
- 합체 누적 뒤 임의 환산 분모

## 6. 성능 예산

### VAR-008: 희귀도 순서 보존

변종의 총 EquivalentContribution 예산은 최종 공식 분모와 같은 순서를 사용합니다.

```text
VariantPowerMultiplier
= FamilyOddsN ^ 0.20

VariantPowerBudget
= BaseTowerPowerBudget × VariantPowerMultiplier
```

계열별 기준 배율:

| 계열 | 기본형 대비 PowerBudget |
|---|---:|
| 인화성 | `×5.4928` |
| 독성 | `×6.3096` |
| 공허 | `×7.2478` |
| 거대 | `×8.7055` |

이 값은 전부 직접 피해에 곱하는 수치가 아닙니다. 개별 변종은 다음 요소에 총 예산을 나눕니다.

```text
기본 행동 강화
+ 계열 고유 효과
+ 역할별 지원·제어 기여
+ 범위·대상 수·타겟 전환
+ 필요하면 느린 템포·제약
```

같은 최종 공식 분모의 일반 타워와 변종은 비슷한 총 기여도 예산을 가져야 합니다. 계열 효과가 실전에서 과도하면 직접 피해를 낮추고, 제약이 크면 다른 부분을 높입니다.

### VAR-009: 완주 비필수

계산상 균형형 계정의 변종 중앙값:

```text
15시간: 2개
30시간: 9개
```

중앙 편성 전투력 증가 상한은 약 0.5% 수준입니다. 따라서 변종은 일반 타워 수집과 메인 완주 계산을 대체하지 않습니다.

희귀 기본형의 변종을 얻은 극소수 계정은 큰 전투력 보상을 받을 수 있습니다. 이는 최종 공식 분모에 맞는 정상적인 RNG 결과입니다.

## 7. 합체

초기 규칙:

- 같은 변종끼리만 합체 가능
- 변종 계보가 명시된 경우만 가능
- 기본형 + 변종 혼합 불가
- 서로 다른 변종 혼합 불가
- 자동 합체 없음
- 보호·편성 수량 제외

각 변종은 대응 계보·전용 계보·합체 불가 중 하나를 카탈로그에 명시합니다.

변종 획득 자체와 합체 재료 수급은 별도 계산입니다. 합체 비용·필요 수량·최종 전투력은 후속 합체 벤치마크에서 확정합니다.

---

## 8. 보호

- 모든 변종은 자동 보호 후보
- 공식 최종 분모가 자동 보호 기준 이상이면 즉시 보호
- 보호 수량은 수동 합체 재료에서 제외
- 편성 중 수량도 기본적으로 합체 재료에서 제외
- 자동 해제·자동 합체 없음

정확한 자동 보호 분모는 인벤토리와 합체 명세에서 확정합니다.

---

## 9. 표시와 타격감

- 기본형과 구분되는 재질·파티클·음향
- 계열을 즉시 알아볼 수 있는 공격 효과
- 거대·공허처럼 실루엣이 중요한 계열은 모션 변경
- 획득 시 공식 기본 `1 / N` 표시
- 희귀도에 맞는 획득 연출
- 연출 축약·건너뛰기 설정 지원
- 일반 공격 카메라 흔들림 없음

세부 기준은 `PRESENTATION_FEEL.md`와 `SETTINGS.md`를 따릅니다.

## 10. 제작

제작 순서:

```text
기본형 완성
→ 허용 계열 결정
→ 계열 PowerBudget 분배
→ 모델 재질·효과 적용
→ 행동 충돌 검사
→ 합체 계보 연결
→ 카탈로그 채택
```

공통 제작 자산:

- 계열별 색·재질·음향 규칙
- 지속 피해·폭발·전염·연쇄 효과 라이브러리
- 거대 모델 크기와 공격 연출 규칙
- 공허 순간이동·공간 왜곡 표현
- 획득·보호·도감 UI

---

## 11. 저장과 환생

영구 유지:

- 계열 해금
- 계열별 허용 범위 단계
- 변종 보유 수량
- 보호 수량
- 도감 기록
- 합체 결과

환생, 스테이지 이동, 서버 이동과 재접속으로 변종 상태를 초기화하지 않습니다. 플레이어 간 거래는 없습니다.

---

## 12. 사용하지 않는 구조

- 성능 변화 없는 색칠 변종
- 같은 변종의 무작위 수치
- 획득 후 감정·재굴림
- 일반 행운으로 계열 티켓까지 이중 압축
- 잠긴 계열 확률을 다른 계열에 재분배
- 한 굴림에서 둘 이상의 변종 지급
- 기본형·변종 혼합 합체
- 서로 다른 계열 혼합 합체
- 자동 합체
- 특정 저항으로 변종 완전 무력화
- 환생 시 변종 소실
- 모든 타워에 모든 변종 강제
- 변종 보유를 V1 메인 완주 조건으로 사용
