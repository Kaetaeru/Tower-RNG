# 타워 고유 확장

- 계층: 게임 기획
- 상태: **Confirmed (Living Document)**
- 구현 상태: 미구현
- 관련 문서: `TOWER_BEHAVIOR.md`, `COMBAT.md`, `LIVE_WAVE.md`, `../technical/TOWER_EXTENSION_FRAMEWORK.md`
- 마지막 정리: 2026-08-02

> 이 문서는 일반 타워 행동 문법만으로 표현하기 어려운 고유 기능을 각 타워에 추가하는 확장 원칙을 정의합니다.
> 한정 타워만을 위한 예외 코드가 아니라, 필요할 때 어떤 타워든 사용할 수 있는 공통 확장 구조를 사용합니다.

---

## 1. 기본 원칙

일반적인 타워는 다음 행동 문법으로 제작합니다.

```text
전투 역할
+ 타겟 정책
+ 이동 방식
+ 행동 루틴
+ 전달 방식
+ 3D 모션
```

그러나 일부 타워는 이 구조만으로 설명하기 어려운 고유 기능을 가질 수 있습니다.

예:

- 전장의 모든 적에게 동시에 천둥을 떨어뜨림
- 플레이어가 일정 시간 직접 조준하고 공격함
- 적이 생성될 때 자동으로 표식을 부여함
- 다른 타워가 치명타를 낼 때 반응함
- 전투 중 별도의 UI, 카메라와 조작 방식을 제공함
- 특정 조건에서 일반 자동 행동을 완전히 다른 행동으로 교체함

이 기능을 구현하기 위해 공통 전투 코어에 타워 이름별 예외문을 추가하지 않습니다.

각 타워 모듈이 선택적으로 **고유 확장**을 등록하고, 공통 확장 런타임이 이를 연결합니다.

---

## 2. 일반 행동과 고유 확장의 관계

고유 확장은 일반 행동을 대체하는 새로운 최상위 타워 종류가 아닙니다.

```text
일반 행동 문법
+ 선택적 고유 확장 0개 이상
```

예:

```text
폭풍 군주
- 일반 행동: Formation + ChargeRelease + TargetArea
- 고유 확장: StormJudgment

조종형 전투기
- 일반 행동: Formation + Channel + Projectile
- 고유 확장: ManualControl
```

하나의 타워는 여러 확장을 동시에 사용할 수 있습니다.

```text
한정 폭풍 전투기
- StormJudgment
- ManualControl
- KillCharge
```

확장끼리 필요한 정보를 전달하거나 특정 사건에 반응할 수 있어야 합니다.

## 3. 확장 가능 영역

고유 확장은 다음 영역을 추가할 수 있습니다.

### 전투 사건 반응

- 타워 생성과 제거
- 편성 및 편성 해제
- 스테이지 시작과 종료
- 적 생성
- 공격 전후
- 피해와 상태 효과 적용
- 치명타
- 적 처치
- 대상 변경
- 자원 변화

### 고유 능력

- 자동 발동 능력
- 일정 주기 능력
- 조건 충족 능력
- 플레이어가 누르는 수동 능력
- 전장 전체 효과
- 타워 또는 대상에게 붙는 지속 효과

### 플레이어 조작

- 직접 조준
- 공격 버튼
- 보조 공격
- 위치 또는 대상 선택
- 일정 시간 동안 타워 직접 조종
- 전용 UI와 카메라

### 고유 상태

- 폭풍 충전량
- 처치 스택
- 조종 가능 시간
- 특수 탄약
- 별도의 변신 단계

### 고유 연출과 생성물

- 전장 전체 연출
- 전용 투사체
- 고유 소환체
- 전용 UI
- 카메라 효과
- 타워 전용 음향과 이펙트

## 4. 전장 전체 효과

전장의 모든 적에게 천둥을 떨어뜨리는 것과 같은 기능은 일반 공격의 타겟 정책을 억지로 확장해서 만들지 않습니다.

고유 능력 확장이 현재 전투 범위의 적을 조회하고, 공통 전투 서비스를 통해 일괄 판정을 요청합니다.

### 확정 원칙

- 일반 스테이지에서 `모든 적`은 기본적으로 해당 플레이어의 개인 전투에 존재하는 적을 뜻합니다.
- 다른 플레이어의 개인 몬스터에는 영향을 주지 않습니다.
- 라이브 웨이브에서는 공동 전투 범위를 사용할 수 있지만, 해당 확장이 공동 전투 사용을 명시적으로 허용해야 합니다.
- 피해량, 치명타, 상태 효과와 처치 판정은 서버가 처리합니다.
- 각 적을 대상으로 별도의 무제한 반복 작업을 만드는 대신 일괄 조회와 일괄 판정 경로를 지원합니다.
- 시각 효과의 개수와 품질은 성능을 위해 별도로 축약할 수 있지만 실제 판정 결과는 동일해야 합니다.

---

## 5. 플레이어 조작형 타워

일부 타워는 일정 시간 동안 플레이어가 직접 조준하고 공격할 수 있습니다.

### 조작 중 자동 행동 정책

타워마다 다음 중 하나를 선택합니다.

```text
Continue
- 기존 자동 행동을 유지하면서 수동 기능을 추가

Pause
- 조작 중 자동 행동을 일시정지하고, 종료 후 이어서 실행

Replace
- 조작 중 자동 행동을 완전히 대체
```

### 확정 원칙

- 플레이어는 공격 의도, 조준 방향, 위치 선택과 버튼 입력만 서버에 보냅니다.
- 플레이어 클라이언트가 피해량, 명중 여부, 대상 목록과 쿨다운 완료를 결정하지 않습니다.
- 서버는 조작 소유자, 타워 편성 상태, 조작 세션, 입력 빈도와 입력 범위를 검증합니다.
- 조작 시작과 종료는 명확한 세션으로 관리합니다.
- 타워 제거, 편성 해제, 플레이어 이탈, 스테이지 종료, 조작 시간 만료와 강제 취소 시 반드시 정리됩니다.
- 카메라, 조작 UI와 로컬 연출은 클라이언트가 담당할 수 있지만 전투 결과는 서버 권한입니다.

---

## 6. 한정 타워와 코드 권한

한정, 이벤트, 변종 또는 고희귀도 여부는 콘텐츠 분류입니다.

한정 타워라고 해서 전투 코어, 다른 플레이어의 데이터 또는 검증되지 않은 서버 기능에 직접 접근하는 특별 권한을 주지 않습니다.

모든 고유 확장은 동일한 확장 인터페이스와 검증 경로를 사용합니다.

차이는 다음으로 만듭니다.

- 등록한 고유 확장의 조합
- 확장의 구체적인 효과
- 고유 모션과 연출
- 발동 조건
- 수치와 지속시간
- 플레이어 조작 방식

---

## 7. 확장 간 연동

한 타워에 여러 확장이 있을 때 서로 직접 내부 구현을 수정하거나 강하게 결합하지 않습니다.

확장 간 연동은 다음 방식으로 처리합니다.

- 타워 인스턴스 범위의 신호 발행과 구독
- 명시적으로 공유되는 읽기 전용 정보
- 공통 Context를 통한 상태 요청

예:

```text
KillCharge 확장
- 적 처치 시 StormChargeChanged 신호 발행

StormJudgment 확장
- StormChargeChanged 신호를 받아 충전 완료 여부 확인

ManualControl 확장
- 충전 완료 시 전용 능력 버튼 활성화
```

확장 하나가 제거되거나 실패해도 다른 확장과 기본 행동이 가능한 범위에서 계속 작동해야 합니다.

---

## 8. 확장 사용 여부

고유 확장은 모든 타워의 필수 구성요소가 아닙니다.

일반 타워는 확장 없이 행동 문법만으로 완성할 수 있어야 합니다.

새 확장을 만들 기준:

- 기존 행동 루틴의 단순한 호출 순서만으로 표현하기 어려움
- 전투 사건을 장기간 구독해야 함
- 별도의 런타임 상태가 필요함
- 플레이어 입력, UI 또는 카메라가 필요함
- 일반 자동 행동의 시작·중단·대체가 필요함
- 다른 확장과 신호를 교환해야 함

단순히 한 번 더 피해를 주거나 다른 이펙트를 재생하는 정도라면 새로운 확장보다 기존 행동 모듈 안에서 처리합니다.

---

## 9. 현재 확정된 방향과 후속 결정

### 확정

- 일반 행동 문법과 고유 확장을 분리합니다.
- 한 타워는 확장을 0개 이상 가질 수 있습니다.
- 확장은 이벤트, 능력, 조작, 상태와 고유 자산을 추가할 수 있습니다.
- 확장끼리 신호를 통해 연동할 수 있습니다.
- 플레이어 조작은 서버 권한 세션으로 관리합니다.
- 전장 전체 효과도 플레이어별 전투 범위를 지킵니다.
- 한정 타워를 코어 예외 코드로 구현하지 않습니다.

### 후속 명세에서 결정

- 확장별 저장 상태 허용 범위
- 수동 능력 UI의 공통 배치 방식
- 조작형 타워와 플레이어 이동의 동시 처리
- 라이브 웨이브에서 타 플레이어에게 보이는 조작 연출
- 확장 이벤트의 정확한 실행 순서와 충돌 처리
- 전장 전체 효과의 최대 동시 연출 수
