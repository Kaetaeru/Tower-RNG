## 요약

타워는 굴리기로 획득하고 ID별 수량으로 보유하는 고정 데이터 개체입니다. 같은 ID는 언제나 같은 능력·행동·외형을 가지며 개별 레벨과 무작위 옵션을 사용하지 않습니다.

첫 출시 일반 굴리기 타워는 최소 50종, 여섯 역할마다 약 8~10종을 목표로 합니다. 공식 기본 분모가 큰 타워는 반드시 더 높은 전투 예산을 가집니다.

---

## 1. 고정 타워 데이터

### TWR-001: 동일 ID의 동일 성능

동일한 `TowerId`는 다음이 같습니다.

- 공식 기본 `1 / N`
- 역할과 공통 기여도 예산
- 기본 전투 능력
- 이동·타겟·행동 루틴
- 외형·모션·효과·음향
- 합체 계보와 허용 변종

### TWR-002: 개별 무작위 성장 없음

사용하지 않음:

- 개별 레벨·경험치
- 무작위 능력치
- 접두·접미사
- 같은 타워의 다른 품질
- 중복 수량만으로 공격력 증가

영구 성장은 스탯 트리와 환생이 담당합니다.

---

## 2. 출시 목표

### TWR-003: 최소 50종

```text
일반 굴리기 타워 최소 50종
+ 변종 타워
+ 합체 전용 상위 타워
```

변종과 합체 전용 결과는 기본 50종에 추가합니다.

### TWR-004: 역할별 8~10종

- 단일 화력
- 광역 화력
- 제어
- 마무리
- 지원
- 대형 사냥

복합 역할은 실제 한 종류로만 계산합니다.

### TWR-005: 행동 다양성

- Formation·Engage·ChargeThrough·Orbit 등 이동
- Impact·Sequence·Burst·Channel·Summon 등 행동
- Contact·Projectile·Beam·Area 등 전달
- 단순 타워와 고유 확장 타워
- 인간형·기계·생물·추상 오브젝트 실루엣

수치와 색상만 바꾼 일반 타워가 대부분이 되지 않게 합니다.

---

## 3. 희귀도와 성능

### TWR-006: 더 희귀하면 반드시 더 강함

공식 기본 분모 `N`이 커질수록 `PowerBudget`이 증가합니다.

```text
RawPowerBudget(N) = (N / 10) ^ 0.20
```

같은 역할에서 공식 분모 순서와 최종 기여도 순서는 반드시 일치합니다.

```text
1 / 998 타워
< 1 / 999 타워
```

서로 다른 역할도 `EquivalentContribution` 기준에서 더 희귀한 타워가 더 높은 총 기여 예산을 가집니다.

### TWR-007: 최소 성능 차이

공식 분모가 매우 가까워 원시 공식 차이가 작더라도 같은 역할의 다음 타워는 이전보다 최소 0.1% 높은 최종 기여도를 가져야 합니다.

정수 피해 반올림으로 차이가 사라지면 내부 고정소수점, 행동 주기, 대상 수 또는 효과량으로 차이를 유지합니다.

### TWR-008: 역할별 강함

희귀 타워의 강함을 공격력 하나로만 표현하지 않습니다.

- 단일 화력: 지속 집중 DPS
- 광역 화력: 기준 밀집도 총 피해
- 제어: 벌어 준 처리시간
- 마무리: 실제 체력 분포의 추가 기여
- 지원: 편성 전체에 더한 기여
- 대형 사냥: 정예·보스 기여

특정 순간의 상성 때문에 결과가 달라질 수 있지만 기준 전투들의 가중 평균에서는 희귀도 순서를 뒤집지 않습니다.

세부 공식은 `BALANCE_MODEL.md`에서 관리합니다.

---

## 4. 타워 데이터

각 타워는 최소한 다음을 가집니다.

- `TowerId`, 표시 이름
- `BaseOddsN` 10진수 문자열
- 보조 등급
- 주·보조 역할
- `RawPowerBudget`, `FinalPowerBudget`
- 기준 `EquivalentContribution`
- 이동·타겟·행동·전달 방식
- 기본 수치와 행동 주기
- 자동 편성 평가 정보
- 모델·모션·효과·음향
- 합체 결과와 변종 관계
- `FeedbackWeight`

실제 목록은 `docs/reference/TOWER_CATALOG.md`에서 관리합니다.

## 5. 보유와 보호

### TWR-009: ID별 수량

```text
견습 궁수 ×17
화염 마법사 ×3
왕실 기사 ×1
```

개별 인스턴스 목록을 만들지 않습니다.

### TWR-010: 보호 수량

타워별로 다음을 저장합니다.

```text
OwnedCount
ProtectedCount
```

- `ProtectedCount`는 `OwnedCount`를 초과할 수 없음
- 보호된 수량은 수동 합체 재료에서 제외
- 공식 기본 분모 기준 자동 보호 가능
- 현재 행운 적용 확률은 보호 기준으로 사용하지 않음

### TWR-011: 편성 수량

편성 수량은 보유 수량, 전체 슬롯과 역할 슬롯을 지킵니다. 동일 타워 전용 상한은 없습니다.

같은 타워를 여러 개 획득했다면 역할 슬롯 범위 안에서 원하는 만큼 사용할 수 있습니다.

---

## 6. 획득과 편성

### TWR-012: 획득 처리

- 보유 수량 증가
- 최초 획득과 도감 기록
- 공식 기본 분모와 확률표 버전 기록
- 희귀 자동 보호
- 자동 편성 재평가 후보
- 희귀 타워 리더보드 후보 갱신

### TWR-013: 자동 편성

자동 편성은 역할 슬롯, 역할 성향과 실제 기여도를 사용합니다.

- 동일 타워라는 이유로 인위적인 감점 없음
- 지원·제어를 표시 DPS만으로 제외하지 않음
- 공식 분모 대신 실제 기준 기여도 사용
- 자동 편성 OFF에서는 새 획득이 현재 편성을 바꾸지 않음

---

## 7. 공통 성장과 큰 수

모든 타워는 다음 계정 성장을 적용받습니다.

- 성능 강화
- 공격속도
- 치명타
- 편성 슬롯
- 환생 보너스

후반 수치는 공통 `MagnitudeNumber` 형식을 사용합니다. 각 타워가 별도 큰 수 구현을 갖지 않습니다.

---

## 8. 외형·행동·타격감

타워는 3D `Model`과 `Basic + 자유 이름 모션 견본`으로 제작합니다.

모든 공격은 다음을 읽을 수 있어야 합니다.

- 준비 동작
- 판정 순간
- 공격자 반동
- 대상 피격 반응
- 역할·희귀도에 맞는 음향과 효과

일반 공격의 타격감을 카메라 흔들림에 의존하지 않습니다. 세부 기준은 `PRESENTATION_FEEL.md`와 `SETTINGS.md`를 따릅니다.

---

## 9. 환생과 거래

환생 후 유지:

- 보유 수량
- 보호 수량
- 도감
- 합체 결과
- 변종 해금
- 편성 데이터

플레이어 간 타워 거래·우편·양도는 지원하지 않습니다.

---

## 10. 사용하지 않는 구조

- 더 희귀한 타워가 기준 기여도에서 더 약함
- 정수 반올림으로 희귀도 차이 소멸
- 개별 타워 레벨·무작위 능력치
- 중복 보유만으로 직접 강화
- 동일 타워 전용 편성 상한
- 자동 편성 OFF 상태 강제 교체
- 환생 시 타워 소실
- 거래를 통한 타워 이전
- 움직임과 피격 반응 없는 피해 숫자만의 공격

---

## 11. 미확정 사항

- 최초 50종 목록과 공식 분모
- 역할별 기준 전투 시나리오
- 보조 등급 명칭
- 자동 편성 평가용 최종 필드
- 도감 공개 정보 범위
- 각 타워의 실제 피드백 등급
