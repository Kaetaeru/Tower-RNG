## 요약

Tower RNG는 자동 전투와 반복 굴리기가 중심이므로 화면이 정적이거나 조작 결과가 무감각하게 느껴져서는 안 됩니다.

**모든 의미 있는 입력과 전투 결과에는 즉각적이고 분명하며 과장된 반응이 있어야 합니다.** UI 클릭, 구매, 굴리기, 타워 공격, 적 피격, 처치, 코인 획득과 환생 모두 시각·움직임·음향 중 둘 이상으로 결과를 전달합니다.

현실적인 움직임보다 읽기 쉽고 기분 좋은 움직임을 우선합니다. 다만 모든 순간을 같은 최대 강도로 표현하지 않고 중요도에 따라 강약을 나눠 큰 순간의 타격감을 보존합니다.

---

## 1. 필수 감각 원칙

### FEE-001: 반응 없는 입력 금지

플레이어가 버튼을 눌렀는데 색이나 숫자만 조용히 바뀌는 상태를 완성으로 보지 않습니다.

모든 유효 입력은 즉시 다음 중 둘 이상을 보여야 합니다.

- 눌림·압축·확대·반동 같은 움직임
- 색·광택·외곽선·파티클 변화
- 짧고 명확한 효과음
- 진동 또는 햅틱
- 상태 변화와 숫자 변화

서버 응답이 필요한 입력도 클라이언트에서 눌림 반응은 즉시 보여 주고, 성공·실패 결과는 서버 응답 후 별도로 표현합니다.

### FEE-002: 과장된 움직임

다음 표현을 적극적으로 사용합니다.

- 사전 동작과 힘 모으기
- 빠른 본동작
- 오버슈트와 되돌아오기
- 스쿼시·스트레치
- 반동과 후속 동작
- 짧은 정지 또는 강조 프레임
- 크기·회전·위치의 의도적인 과장

움직임이 물리적으로 정확하더라도 약하게 느껴진다면 더 과장된 표현을 우선합니다.

### FEE-003: 판정과 연출 분리

강한 연출이 실제 판정이나 메뉴 반응을 늦추지 않습니다.

- 서버 전투 판정을 화면 흔들림이나 장식 애니메이션이 정지시키지 않음
- UI 버튼은 긴 애니메이션이 끝나기 전에 입력 결과를 반영할 수 있음
- 로컬 미세 정지와 강조는 가능하지만 서버 전체 시간을 멈추지 않음
- 장식 효과가 끝나지 않아도 다음 웨이브와 굴리기 진행 가능

## 2. UI 클릭과 메뉴 피드백

### FEE-004: 기본 버튼 반응

기본 버튼은 다음 흐름을 사용합니다.

```text
포인터 진입 또는 선택
→ 밝기·외곽선·약한 확대
→ 누름 순간 압축
→ 짧은 클릭음과 햅틱
→ 성공 시 오버슈트하며 복귀
```

모바일 터치에서도 같은 정보를 전달하며 Hover에만 의존하지 않습니다.

### FEE-005: 성공·실패의 다른 감각

성공:

- 앞으로 튀거나 열리는 방향의 움직임
- 밝아지는 색과 상승 음
- 재화·노드·카드의 연결 연출

실패 또는 잠금:

- 짧은 좌우 흔들림이나 저항감
- 닫히는 낮은 음
- 필요한 코인·선행 노드·환생 횟수를 즉시 표시

실패 애니메이션으로 조작을 오래 막지 않습니다.

### FEE-006: 구매와 성장

스탯 구매, 문 해금과 환생은 단순 숫자 감소로 끝내지 않습니다.

- 코인이 목표로 빨려 들어가는 연출
- 구매 노드의 팽창·점등·연결선 활성화
- 가격 숫자의 감소와 보유 코인의 보간
- 새 가지와 기능의 시각적 개방
- 중요한 해금은 짧은 전용 음향과 화면 강조

### FEE-007: 굴리기와 희귀 획득

굴리기 결과는 희귀도에 따라 연출 강도를 높입니다.

- 일반 결과도 짧은 카드·아이콘 반응 제공
- 희귀 결과는 사전 긴장, 색 변화, 충격 프레임과 강한 음향 사용
- 매우 희귀한 결과는 편대와 월드에서도 잠시 존재감을 보여 줌
- 연출은 건너뛰기와 자동 축약 설정 지원
- 전투와 코인 수집을 장시간 막지 않음

## 3. 전투 타격감

### FEE-008: 공격의 세 단계

공격은 가능한 범위에서 다음 세 단계를 읽을 수 있어야 합니다.

```text
Anticipation
힘을 모으고 방향을 보여 줌

Impact
빠른 본동작과 명확한 접촉 순간

Follow-through
반동·잔상·회복 동작
```

빠른 공격도 세 단계를 완전히 생략하기보다 매우 짧게 압축합니다.

### FEE-009: 피격 순간의 다중 피드백

중요한 피해 판정은 다음 중 여러 요소를 결합합니다.

- 공격자의 반동 또는 자세 변화
- 대상의 짧은 밀림·흔들림·스쿼시
- 타격 지점 파티클과 섬광
- 공격 종류에 맞는 충격음
- 피해 숫자의 크기·속도·방향 변화
- 로컬 화면 흔들림
- 지원 기기의 햅틱
- 로컬 마이크로 히트스톱 또는 강조 프레임

마이크로 히트스톱은 전투 서버를 멈추는 기능이 아니라 공격자 또는 관전자 클라이언트의 짧은 시각 강조입니다.

### FEE-010: 처치와 보상 연결

적 처치는 공격 종료가 아니라 보상 획득 루프의 시작으로 보여야 합니다.

```text
강한 마지막 피격
→ 사망 반응
→ 코인 분출·낙하
→ 가까운 코인 병합
→ 자석 흡입
→ HUD 코인 증가
```

각 단계의 움직임과 음향을 연결해 타워의 공격이 실제 성장으로 이어졌다는 느낌을 줍니다.

### FEE-011: 보스와 큰 공격

보스 등장, 강한 공격, 보스 처치와 환생은 일반 공격보다 명확하게 높은 연출 등급을 사용합니다.

- 더 큰 사전 동작과 실루엣
- 넓은 충격 효과
- 낮은 음역과 다층 음향
- 제한적인 카메라 흔들림
- 월드 또는 HUD의 짧은 강조

모든 일반 공격을 보스 처치와 같은 강도로 만들지 않습니다.

## 4. 강약 계층

### 미세 피드백

- 일반 버튼
- 일반 굴림
- 작은 코인 획득
- 약한 일반 공격

### 중간 피드백

- 스탯 구매
- 편성 변경
- 치명타
- 웨이브 시작과 종료
- 희귀 타워 획득

### 대형 피드백

- 문 해금
- 새로운 트리 분야 개방
- 보스 등장과 처치
- 극희귀 타워 획득
- 환생

같은 종류의 사건도 반복 빈도가 높으면 연출 길이를 줄이고, 강도와 정보는 유지합니다.

---

## 5. 가독성·접근성·성능

### FEE-012: 정보 우선

과장된 연출이 다음을 가리면 안 됩니다.

- 코인 위치
- 스테이지 문
- 보스와 주요 몬스터
- 퀵 편성 HUD
- 구매 가능 여부
- 현재 웨이브

### FEE-013: 사용자 설정

다음 설정을 제공합니다.

- 화면 흔들림 강도
- 번쩍임과 밝은 섬광 감소
- 피해 숫자 표시량
- 다른 플레이어 효과 축약
- 햅틱 ON/OFF
- 희귀 획득 연출 자동 축약
- 감소된 움직임 모드

감소 설정을 사용해도 성공·실패와 위험 정보를 잃지 않습니다.

### FEE-014: 성능 예산

- 반복 파티클과 피해 숫자 풀링
- 다른 플레이어 전투 효과 축약
- 화면 밖 또는 중요도가 낮은 효과 간소화
- 같은 프레임의 반복 효과 묶음 처리
- 실제 판정 수와 시각 효과 수를 반드시 일치시킬 필요 없음

연출을 줄이더라도 공격이 맞았다는 핵심 피드백은 남깁니다.

---

## 6. 완료 기준

다음 중 하나라도 부족하면 해당 UI나 공격 연출은 감각 측면에서 완료되지 않은 것으로 봅니다.

```text
[ ] 입력 순간 즉시 반응하는가
[ ] 성공과 실패가 다른 감각으로 구분되는가
[ ] 공격의 방향과 접촉 순간을 읽을 수 있는가
[ ] 적이 맞았다는 반응이 있는가
[ ] 음향 또는 햅틱이 움직임과 일치하는가
[ ] 중요한 사건이 일반 사건보다 강하게 느껴지는가
[ ] 연출이 실제 판정과 다음 행동을 불필요하게 지연하지 않는가
[ ] 감소된 움직임과 화면 흔들림 설정을 지원하는가
[ ] 다수의 타워와 적이 있어도 핵심 정보가 보이는가
```

---

## 7. 사용하지 않는 구조

- 눌러도 즉시 반응하지 않는 정적인 버튼
- 공격자가 움직이지 않고 피해 숫자만 나오는 일반 공격
- 적이 맞아도 아무 반응이 없는 전투
- 모든 사건을 같은 최대 강도로 표현
- 긴 연출로 굴리기·전투·메뉴를 반복적으로 정지
- 서버 전체 시간을 멈추는 히트스톱
- 접근성 설정 없이 강한 흔들림과 섬광 강제

---

## 8. 미확정 사항

- 기본 화면 흔들림 강도
- 플랫폼별 햅틱 패턴
- 피격 숫자의 최종 스타일
- 공격 등급별 기본 연출 예산
- 희귀도별 굴리기 연출 길이
- 감소된 움직임 모드의 정확한 축약 규칙
