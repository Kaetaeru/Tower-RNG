## 요약

일반 굴리기는 한 번에 정확히 타워 하나를 지급합니다. 각 타워는 공식 기본 확률 `1 / N`을 가지며 분모는 임의 정밀도 10진수 문자열로 저장합니다.

플레이어에게는 공식 기본 확률만 표시합니다. 스테이지, 환생 스탯 토큰, 포션과 특수 주사위가 반영된 현재 유효 확률은 표시하지 않습니다.

불변조건:

- 한 굴림 한 결과
- 빈 결과 없음
- 공식 확률 합 정확히 100%
- 행운 적용 후 합도 100%
- 희귀 순서 역전 없음
- 흔한 결과 완전 소멸 없음
- 기존 중·고희귀 분모를 신규 콘텐츠 때문에 몰래 낮추지 않음

---

## 1. 공식 기본 확률

### RNG-001: `1 / N`

```text
BaseOddsN: 양의 정수의 10진수 문자열
공식 기본 확률: 1 / BaseOddsN
```

예:

```text
1 / 10
1 / 1,000
1 / 12,500
1 / 1,000,000,000,000
1 / 100,000,000,000,000,000,000
```

V1 일반 굴리기 최고 기준:

```text
BaseOddsN = "100000000000000000000"
공식 기본 확률 = 1 / 10^20
```

### RNG-002: 표시

표시:

- 공식 기본 `1 / N`
- 보조 등급·색상
- 행운 스탯과 출처
- 황금·다이아몬드 상태

표시하지 않음:

- 현재 행운 적용 후 `1 / N`
- 실시간 결과별 백분율
- 내부 압축값·정규화 가중치
- 다른 타워의 감소한 확률

큰 분모는 카드에서 축약할 수 있지만 상세 정보에는 전체 값을 제공합니다.

---

## 2. 단일 결과 확률표

### RNG-003: 정확한 합

```text
Σ(1 / BaseOddsN) = 1
```

카탈로그를 하나의 비중첩 표로 컴파일합니다.

```text
공식 단위분수
→ 임의 정밀도 합 검증
→ 비중첩 구간 컴파일
→ 난수 선택
→ 정확히 한 결과 지급
```

50자리 V1 사다리는 정확한 유리수 합 1을 통과했습니다.

### RNG-004: 공통 확률 예비분

- 신규 일반 타워는 저희귀 CommonReserve에서 우선 확률 확보
- 기존 중·고희귀 공식 분모 유지
- 빈 결과를 예비분으로 사용하지 않음
- 변경되는 저희귀 분모는 업데이트 전에 공개

### RNG-005: 실패 조건

- 공식 합이 1이 아님
- 행운 적용 합이 1이 아님
- 중복 ID
- 잘못된 분모 문자열
- 희귀 순서 역전
- 예비분보다 큰 신규 배정

잘못된 표를 런타임에서 조용히 반올림·정규화해 숨기지 않습니다.

---

## 3. 큰 분모 처리

### RNG-006: 데이터

```text
BaseOddsN: decimal string
```

### RNG-007: 런타임

- 임의 정밀도 정수·유리수 검증
- 충분한 정밀도의 난수 구간
- 고정 seed 재현 테스트
- 시뮬레이션용 빠른 컴파일 캐시
- 공식 분모를 부동소수점 `number`로 덮어쓰지 않음

일반 `math.random()` 한 번으로 `10^20` 분모를 직접 표현했다고 간주하지 않습니다.

## 4. 로그 희귀도 압축

### RNG-008: 확률 변환

```text
BaseLogOdds = log10(BaseOddsN)
AdjustedLogOdds = 1 + (BaseLogOdds - 1) / Compression
RawAdjustedWeight = 10 ^ (-AdjustedLogOdds)
FinalWeight = RawAdjustedWeight / Σ(RawAdjustedWeight)
```

- `Compression = 1`이면 공식 기본 확률표
- Compression이 커지면 로그 희귀도 간격이 압축됨
- 더 희귀한 결과의 순서는 유지됨
- 최종 정규화 뒤 전체 합은 1

## 5. V1 잠정 행운 계수

### RNG-009: 기본 압축값

```text
BaseCompression
= 1
+ 0.245 × (CurrentStage - 1)
+ 0.040 × AllocatedLuckTokens
+ TemporaryCompressionBonus
```

상태: **Confirmed (Provisional Balance)**

항목:

- `CurrentStage`: 현재 입장한 일반 스테이지 1~15
- `AllocatedLuckTokens`: 환생 스탯 토큰 중 행운에 배분한 수량
- `TemporaryCompressionBonus`: 포션·허용된 제한적 부스트, 아직 미확정

환생 횟수 자체는 행운을 직접 올리지 않습니다. 플레이어가 행운에 토큰을 배분해야 합니다.

### RNG-010: 굴림별 상한

```text
일반 굴림
Compression = clamp(BaseCompression, 1.00, 5.40)

황금 굴림
Compression = clamp(BaseCompression + 0.25, 1.00, 5.65)

다이아몬드 굴림
Compression = clamp(BaseCompression + 0.65, 1.00, 6.05)
```

황금·다이아몬드는 일반 굴림이 상한에 도달한 뒤에도 더 높은 상한을 사용합니다.

### RNG-011: 스테이지 기본값

토큰·포션 없는 일반 굴림:

| 스테이지 | Compression |
|---:|---:|
| 1 | 1.000 |
| 3 | 1.490 |
| 6 | 2.225 |
| 9 | 2.960 |
| 12 | 3.695 |
| 15 | 4.430 |

높은 스테이지 행운은 처치 여부와 무관하게 적용됩니다. 높은 문을 열고 행운만 받은 뒤 낮은 스테이지에서 파밍하는 전략을 허용합니다.

### RNG-012: 토큰 효과

```text
행운 배분 토큰 1개
→ BaseCompression +0.040
```

스테이지 15에서는 약 25개로 일반 굴림 상한에 도달합니다.

## 6. 시뮬레이션 결과

기준:

- 50자리 공식 확률 사다리
- 최고 타워 `1 / 10^20`
- 첫 79초 뒤 굴리기 간격 3.6초
- 매 10번째 황금
- 매 100번째 다이아몬드
- 중앙 스테이지 도달 경로

균형 행운 배분 시나리오:

```text
최초 30분 이후 행운에 평균 1.50토큰/시간 배분
```

최고 타워 누적 획득률:

| 활성 플레이 | 누적 확률 |
|---:|---:|
| 12시간 | 1.549% |
| 13.5시간 | 3.012% |
| 15시간 | 4.661% |
| 20시간 | 11.007% |
| 25시간 | 17.062% |
| 30시간 | 22.705% |

목표 통과:

```text
중앙 V1 완주 13.5~15시간: 3~5%
V1 숙련 25~30시간: 15~25%
```

토큰 지급량과 실제 분배가 정해지면 다시 검증합니다.

## 7. 특수 주사위

### RNG-013: 황금

- 매 10번째 굴림
- BaseCompression `+0.25`
- 상한 `5.65`
- 특정 타워 확정 지급 아님

### RNG-014: 다이아몬드

- 매 100번째 굴림
- 황금을 대체
- BaseCompression `+0.65`
- 상한 `6.05`
- 특정 타워 확정 지급 아님

주기는 전체 굴림 횟수로 저장하며 접속 종료·스테이지 이동·과부하·환생으로 초기화하지 않습니다.

## 8. 현재 확률 비공개

- 인벤토리 카드에 유효 확률 미표시
- 굴리기 화면에 유효 분모 미표시
- 리더보드는 공식 분모 사용
- 획득 연출도 공식 분모 사용
- 서버 로그·밸런스 도구에서는 내부값 사용 가능

플레이어는 행운에 배분한 토큰, 현재 스테이지와 활성 부스트를 확인할 수 있습니다.

---

## 9. 변종 판정

```text
일반 타워 결과 선택
→ 허용·해금된 변종 확인
→ 별도 변종 판정
→ 기본형 또는 변종 지급
```

변종의 최종 공식 확률:

```text
기본 타워 공식 확률 × 변종 기본 판정 확률
```

- 임의 정밀도 문자열 사용
- 미해금 계열 판정 없음
- 현재 변종 유효 확률 미표시
- 변종 공식 희귀 순서 유지

변종 행운 계수는 별도 검증합니다.

## 10. 콘텐츠 추가 정책

- 기존 중·고희귀 `BaseOddsN` 유지
- 신규 타워는 CommonReserve 우선 사용
- 공식 확률 변경 시 이전·신규 값을 공개
- 확률표 버전 저장
- 획득 당시 공식 분모를 기록 가능

---

## 11. 검증 요구사항

- 공식 합 정확히 1
- 모든 압축 구간 최종 합 1
- 희귀 순서 역전 없음
- 한 굴림 한 결과
- 흔한 타워 확률이 0이 아님
- 황금·다이아몬드 주기 정확성
- 큰 분모 결과의 누적 도달 가능성
- 고정 seed 재현
- 환생 토큰 배분 즉시 캐시 재계산
- 스테이지 이동 즉시 캐시 교체
