## 요약

Tower RNG의 일반 굴리기는 한 번에 정확히 한 개의 타워를 지급합니다. 각 타워는 공식 기본 확률을 `1 / N`으로 가지며 `N`은 `999,999`에서 끝나지 않고 필요에 따라 수십억·수조·그 이상으로 확장할 수 있습니다.

플레이어에게는 **공식 기본 확률만 표시**합니다. 현재 행운, 스테이지, 포션과 특수 주사위가 반영된 실시간 유효 확률 또는 현재 `1 / N`은 표시하지 않습니다.

확률과 행운은 다음 불변조건을 지킵니다.

- 한 굴림에 결과 하나
- 빈 결과 없음
- 공식 기본 확률의 합은 정확히 100%
- 행운 적용 후에도 전체 확률은 정확히 100%
- 더 희귀한 타워가 더 흔한 타워보다 높은 확률이 되는 순서 역전 없음
- 기존 희귀 타워의 공식 확률을 신규 콘텐츠 때문에 몰래 낮추지 않음

---

## 1. 공식 기본 확률

### RNG-001: `1 / N`이 기준

각 일반 굴리기 타워는 다음 값을 가집니다.

```text
BaseOddsN: 양의 정수
공식 기본 확률: 1 / BaseOddsN
```

예:

```text
1 / 10
1 / 998
1 / 999
1 / 125,000
1 / 999,999
1 / 10,000,000
1 / 1,000,000,000,000
```

`BaseOddsN`은 일반 숫자형에 고정하지 않고 **10진수 문자열**로 저장합니다. 따라서 IEEE-754 정수 정밀도와 무관하게 매우 큰 분모를 카탈로그에 기록할 수 있습니다.

### RNG-002: 표시

표시하는 정보:

- 공식 기본 `1 / N`
- 보조 등급과 색상
- 현재 행운 수치 또는 행운 배율
- 황금·다이아몬드 주사위 상태

표시하지 않는 정보:

- 현재 행운 적용 후 `1 / N`
- 실시간 유효 확률 백분율
- 내부 정규화 가중치
- 다른 타워의 감소한 확률

큰 분모는 카드에서 축약할 수 있지만 상세 정보에서는 전체 숫자를 확인할 수 있어야 합니다.

## 2. 단일 결과 확률표

### RNG-003: 확률표 전체 컴파일

타워별로 서로 독립된 성공 판정을 반복하지 않습니다. 전체 카탈로그를 하나의 비중첩 확률표로 컴파일하고 단일 난수를 하나의 결과에 대응시킵니다.

```text
카탈로그의 공식 단위분수
→ 전체 합계 검증
→ 비중첩 확률 구간 컴파일
→ 단일 난수 생성
→ 정확히 하나의 결과 지급
```

공식 기본 확률들의 합은 정확히 1이어야 합니다.

```text
Σ(1 / BaseOddsN) = 1
```

확률 컴파일러는 임의 정밀도 유리수로 합계를 검사합니다. 부동소수점 반올림으로 100%를 맞추지 않습니다.

### RNG-004: 공통 확률 예비분

신규 타워 추가를 위해 낮은 희귀도의 공통 확률 영역에 `CommonReserve`를 둡니다.

- 기존 중·고희귀 타워의 공식 `1 / N`은 고정
- 신규 일반 타워는 우선 `CommonReserve`의 확률을 사용
- 예비분은 지정된 일반 타워들의 단위분수 조합으로 실제 결과를 지급
- 새 타워 추가 뒤에도 빈 결과는 없음
- 변경되는 일반 타워 확률은 업데이트 전에 명시

컴파일러는 예비분을 정확한 단위분수들의 합으로 다시 분해할 수 있습니다. 결과적으로 모든 표시 확률은 계속 실제 `1 / N`입니다.

### RNG-005: 확률표 검증 실패

다음 상태에서는 빌드 또는 콘텐츠 로드를 실패시킵니다.

- 공식 확률 합이 100%가 아님
- `BaseOddsN`이 1보다 작음
- 중복 ID
- 예비분보다 큰 신규 확률 배정
- 임의 정밀도 파싱 실패
- 행운 적용 뒤 희귀 순서 역전

런타임에서 임의 정규화로 잘못된 카탈로그를 조용히 보정하지 않습니다.

## 3. 매우 큰 분모 처리

### RNG-006: 임의 정밀도 확률 계약

구현은 다음을 지원해야 합니다.

- `BaseOddsN`을 문자열로 직렬화
- 임의 정밀도 정수·유리수로 카탈로그 검증
- 가장 큰 분모보다 충분히 높은 정밀도의 난수 구간
- 고정된 seed가 같은 결과를 재현하는 테스트 모드
- 수백만·수십억 회 시뮬레이션을 위한 빠른 컴파일 표현

구체적인 큰 정수 라이브러리와 확률 트리 형식은 시스템 명세에서 정합니다. 일반 `math.random()`의 한 번 호출만으로 거대한 분모를 직접 표현했다고 간주하지 않습니다.

### RNG-007: 데이터와 런타임 분리

카탈로그의 권위 값:

```text
BaseOddsN: decimal string
```

런타임 컴파일 값:

```text
정규화된 확률 구간
임의 정밀도 정수 조각
탐색용 확률 트리 또는 테이블
```

런타임 최적화를 위해 공식 분모를 `number`로 덮어쓰지 않습니다.

## 4. 행운 모델

### RNG-008: 로그 희귀도 압축

행운은 기본 확률에 단순히 곱한 뒤 끝내지 않습니다. 기본 분모의 로그 거리를 압축해 희귀 결과를 끌어올리고, 마지막에 전체 가중치를 다시 100%로 맞춥니다.

기본 개념:

```text
BaseLogOdds = log10(BaseOddsN)
Compression >= 1
AdjustedLogOdds = 1 + (BaseLogOdds - 1) / Compression
RawAdjustedWeight = 10 ^ (-AdjustedLogOdds)
FinalWeight = RawAdjustedWeight / Σ(RawAdjustedWeight)
```

- `Compression = 1`이면 공식 기본 확률표와 같음
- 행운이 증가하면 `Compression`이 완만하게 증가
- `1 / 10` 부근의 흔한 결과는 변화가 작음
- 극희귀 결과는 로그 거리 압축 효과를 크게 받음
- 분모가 큰 타워의 희귀 순서는 유지됨

정확한 행운→압축 변환식과 소프트캡은 밸런스 시뮬레이션에서 확정합니다.

### RNG-009: 행운 입력

행운 입력:

- 스탯 트리 영구 행운
- 환생 행운
- 현재 스테이지 행운
- 행운 포션
- VIP 또는 허용된 제한적 유료 행운
- 황금 주사위
- 다이아몬드 주사위

이 값들은 서버에서 하나의 `LuckScore`로 합성한 뒤 로그 압축 계수로 변환합니다.

### RNG-010: 특수 주사위

황금·다이아몬드 주사위는 특정 타워의 확률을 직접 곱하지 않습니다.

```text
기본 LuckScore
× 황금 또는 다이아몬드 보정
→ Compression 계산
→ 전체 확률표 재컴파일 또는 캐시 선택
```

주기가 겹치면 다이아몬드 주사위가 황금을 대체합니다.

### RNG-011: 현재 확률 비공개

행운이 적용된 내부 확률은 서버 계산용입니다.

- 인벤토리 카드에 현재 확률 미표시
- 굴리기 화면에 현재 분모 미표시
- 리더보드에는 공식 기본 분모만 사용
- 획득 연출에도 공식 기본 분모 사용

플레이어는 행운 수치가 증가했다는 사실과 증가 원인을 확인할 수 있지만, 현재 결과별 확률표를 직접 보지는 않습니다.

## 5. 변종 판정

### RNG-012: 기본 타워 뒤 별도 판정

변종은 기본 타워 선택 이후의 별도 판정으로 처리할 수 있습니다.

```text
일반 타워 결과 선택
→ 해당 타워의 허용 변종 확인
→ 해금된 변종 계열 판정
→ 기본형 또는 변종 지급
```

각 변종의 카탈로그에는 최종 공식 기본 확률을 기록합니다.

```text
변종 최종 기본 확률
= 기본 타워 기본 확률
× 변종 기본 판정 확률
```

변종 분모는 기본 분모보다 훨씬 커질 수 있으며 같은 임의 정밀도 문자열 형식을 사용합니다.

### RNG-013: 변종 행운

일반 행운과 합체 누적이 변종 판정에 영향을 줄 수 있지만 다음을 지킵니다.

- 변종 계열 미해금 시 판정하지 않음
- 현재 변종 확률 미표시
- 변종끼리의 공식 희귀 순서 유지
- 기본형 지급 확률을 음수로 만들지 않음

정확한 변종 행운 계수는 변종 명세에서 정합니다.

## 6. 콘텐츠 추가 정책

### RNG-014: 기존 공식 희귀도 보호

신규 타워 추가 시 기본 원칙:

- 기존 중·고희귀 타워의 `BaseOddsN` 유지
- 공통 예비 확률 또는 명시된 일반 타워 구간에서 확률 확보
- 기존 극희귀 결과를 업데이트마다 더 희귀하게 만들지 않음
- 공식 확률 변경 시 변경 대상과 이전·신규 값을 공개

### RNG-015: 확률 버전

확률표에는 버전을 둡니다.

```text
ProbabilityTableVersion
```

획득 기록은 당시 버전을 함께 저장할 수 있습니다. 리더보드의 현재 희귀 순위는 최신 카탈로그 공식 분모를 사용하되, 프로필에는 획득 당시 공식 분모도 기록할 수 있습니다.

## 7. 시뮬레이션과 검증

출시 전 필수 검증:

- 공식 확률 합계 100%
- 모든 행운 구간에서 합계 100%
- 희귀 순서 역전 없음
- 한 굴림 한 결과
- 빈 결과 없음
- 황금·다이아몬드 주기 정확성
- 큰 분모 결과의 통계적 도달 가능성
- 고행운에서 흔한 타워가 완전히 사라지지 않음
- 신규 타워 추가 전후 고정 희귀 타워 확률 동일

극희귀 결과는 실제 샘플만으로 오차를 검증하기 어려우므로 확률표의 수학적 검증과 결정론적 경계 테스트를 함께 사용합니다.

## 8. 사용하지 않는 구조

- 독립 판정 여러 개가 동시에 성공한 뒤 임의로 하나 선택
- 희귀도 순서대로 판정해 앞선 결과가 뒤 결과의 실제 확률을 왜곡
- 공식 `1 / N`과 다른 확률을 표시
- 현재 행운 적용 `1 / N` 표시
- 빈 결과
- 일반 `number` 하나에 거대한 분모를 강제로 저장
- 신규 타워 추가 때 기존 극희귀 확률을 조용히 하향
- 행운 때문에 더 희귀한 타워가 더 흔한 타워보다 높은 확률이 되는 역전
- Robux를 직접 소비하는 반복 굴리기

## 9. 미확정 사항

- 최초 50종의 실제 공식 분모
- `CommonReserve`의 최초 크기와 일반 타워 분배
- 행운 점수에서 압축 계수로 변환하는 최종 공식
- 행운 소프트캡
- 다이아몬드 주사위 보정값
- 변종 기본 판정 확률과 합체 누적 영향
- 임의 정밀도 확률 컴파일러의 구체적인 자료구조
