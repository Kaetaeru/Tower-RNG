## 요약

환생은 진행을 처음으로 되돌리는 프레스티지가 아니라, 전투로 모은 **Defense XP를 영구 스탯 토큰으로 전환하는 연속 성장 행동**입니다.

환생 시 초기화되는 영구 상태는 Defense XP뿐입니다.

```text
유지
- 코인
- 열린 스테이지 문
- 현재 위치와 활성 스테이지
- 현재 웨이브와 전투
- 타워·스탯·도감·합체·변종

변경
- Defense XP → 0
- RebirthCount +1
- 미사용 환생 스탯 토큰 지급
```

첫 환생 요구량은 `7,000 Defense XP`이며, 기존 첫 경제 벤치마크의 도달 시간 `7.80~14.34분`은 그대로 유효합니다. 다만 환생 뒤 코인과 문을 다시 모으는 이전 순환 구조는 폐기합니다.

---

## 1. Defense XP

### REB-001: 환생 전용 진행도

```text
Defense XP
= 처치한 SpawnCost
× StageRewardScale
× BossModifier
```

- 일반 몬스터 BossModifier: 1.00
- 보스 본체 BossModifier: 1.15
- 코인 수집 여부와 무관하게 자동 지급
- 베이스에 도달한 몬스터는 지급하지 않음
- 오프라인에는 증가하지 않음
- 코인 또는 Robux로 직접 구매하지 않음

첫 버전은 별도 웨이브 완료 XP 보너스를 사용하지 않습니다.

### REB-002: 실행 조건

```text
현재 Defense XP >= 다음 환생 요구 XP
→ 환생 가능
```

- 자동 실행 없음
- 전투 중에도 플레이어가 원하는 시점에 실행 가능
- 요구량을 채운 뒤 계속 파밍 가능
- 초과 XP는 환생 시 기본적으로 이월하지 않음

## 2. 요구량과 시간

### REB-003: 첫 환생

```text
FirstRebirthXP = 7,000
```

검증 결과:

| 소비 성향 | 첫 환생 범위 |
|---|---:|
| 균형 소비 | 7.96~13.41분 |
| 문 우선 | 7.80~14.34분 |
| 트리 우선 | 9.63~12.70분 |

첫 환생까지의 경제·전투 계산은 변경되지 않습니다. 환생 이후에는 코인과 문이 유지되므로 두 번째 이후 환생은 새 연속 진행 모델로 다시 계산합니다.

### REB-004: 이후 환생

초기 방향:

- 두 번째 환생 약 15~25분 목표
- 초기 여러 회 약 20~40분 중심
- 중기 이후 점진적으로 증가
- 고정 대기시간·일일 제한 없음

초기 요구량 후보:

```text
RequiredDefenseXP(r)
= 7,000 × (r + 1)^1.65
```

첫 항만 검증되었습니다. 코인·문 초기화가 사라졌으므로 지수 `1.65`는 반드시 다시 시뮬레이션한 뒤 확정합니다.

## 3. 환생 스탯 토큰

### REB-005: 토큰 지급

환생 성공 시 영구 스탯 토큰을 지급합니다.

```text
RebirthCount +1
UnspentRebirthStatTokens + TokenReward
DefenseXP = 0
```

확정된 원칙:

- 토큰은 계정 영구 보유
- 사용하지 않은 토큰은 다음 환생으로 이월
- 환생 횟수만으로 자동 코인·행운 배율을 주지 않음
- 실제 영구 보너스는 플레이어가 배분한 토큰에서 계산
- 무작위 보상이나 실패 확률 없음

아직 미확정:

- 환생당 토큰 지급량
- 환생 횟수에 따른 추가 토큰
- 배분 가능한 스탯 목록
- 토큰 재분배 가능 여부와 비용

### REB-006: 스탯 배분

프로필은 다음을 저장합니다.

```text
RebirthStatTokensEarned
UnspentRebirthStatTokens
RebirthStatAllocations[StatId]
```

행운 스탯의 첫 잠정 계수는 다음과 같습니다.

```text
행운 배분 토큰 1개
→ 로그 희귀도 Compression +0.040
```

전체 행운 공식과 상한은 `RNG_PROBABILITY.md`와 `V1_LUCK_COMPRESSION_BENCHMARK.md`를 따릅니다.

행운 외 스탯은 아직 확정하지 않습니다. 후보를 문서에 확정값처럼 미리 등록하지 않습니다.

## 4. 환생 실행 결과

### REB-007: 초기화

```text
Defense XP만 0으로 초기화
```

초기화하지 않음:

- 코인
- 열린 문
- 최고 도달 스테이지
- 마지막 활동 스테이지
- 현재 위치
- 현재 웨이브·몬스터·보스·베이스
- 바닥 코인
- 타워 타겟·투사체·소환체
- 포션 활성 시간

환생 때문에 로비로 이동하거나 웨이브 1로 되돌리지 않습니다.

### REB-008: 유지

- 보유 타워·보호·편성
- 도감·최초 획득 기록
- 스탯 트리 노드
- 합체·변종 진행
- 굴림 횟수와 특수 주사위 진행
- 연금 정수와 포션
- 오프라인 업그레이드
- 열린 문과 텔레포터 목적지
- 최초 튜토리얼 완료 상태
- 환생 횟수·토큰·토큰 배분
- 설정

## 5. UI 흐름

환생 가능 상태에는 다음을 표시합니다.

- 현재 Defense XP와 요구량
- 이번 환생에서 받을 스탯 토큰
- 환생 뒤 Defense XP가 0이 된다는 설명
- 코인·문·현재 전투는 유지된다는 설명
- `환생` 버튼
- `스탯 배분` 진입

남은 코인을 소비하라는 경고, 문 재잠금 경고와 로비 이동 경고는 표시하지 않습니다.

환생 직후:

```text
토큰 획득 연출
→ 미사용 토큰 수 갱신
→ 현재 전투 계속
```

연출이 자동 전투와 굴리기를 장시간 멈추지 않게 합니다.

---

## 6. 저장과 원자성

환생은 하나의 원자적 프로필 변경입니다.

```text
Defense XP 요구량 검증
→ 중복 TransactionId 검증
→ RebirthCount 증가
→ 토큰 지급
→ Defense XP 0
→ 중요 저장 큐 등록
```

실패한 요청은 XP를 초기화하거나 토큰을 지급하지 않습니다. 버튼 연타와 서버 지연으로 같은 환생을 두 번 처리하지 않습니다.

## 7. 사용하지 않는 구조

- 환생 코인 비용
- 환생 시 코인 초기화
- 환생 시 문 재잠금
- 환생 시 로비 강제 이동
- 환생 시 웨이브·전투 초기화
- 환생 횟수에 따른 자동 고정 스탯 지급
- Defense XP 유료 직접 구매
- 오프라인 Defense XP
- 초과 XP로 여러 환생 즉시 연속 실행
- 타워·도감·스탯·합체·변종 초기화
- 환생 실패 확률과 무작위 토큰 보상
